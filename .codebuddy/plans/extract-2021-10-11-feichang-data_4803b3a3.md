## User Requirements

- Extract data from `e:/term/navi_navy/output/merged_feichang_ships.parquet` for the date range **2021-10-01 00:00:00 UTC to 2021-11-30 23:59:59 UTC** (or left-closed/right-open 2021-12-01).
- Output a CSV file `e:/term/navi_navy/output/merged_feichang_ships_2021-10-01_2021-11-30.csv` with the **same column format** as the existing `merged_feichang_ships_2021-10-01_2021-10-31.csv`.
- Reuse or align with existing scripts in `scripts/`; check whether a one-click extraction script already exists.
- After extraction, update the Vercel deployment pipeline to use the new 10-11 CSV instead of the 10-only CSV.

## Tech Stack

- **Data extraction**: Python + pandas / pyarrow (parquet reading and time-range filtering).
- **Frontend/API data generation**: Existing Node.js scripts (`build-data.js`, `extract10k.cjs`, `compress-csv.js`).
- **Deployment**: Existing `deploy.ps1` (PowerShell + git + Vercel).

## Implementation Approach

1. **No existing one-click script**: `scripts/merge_feichang_csv.py` merges raw single-ship CSVs from `sourcedata/肥肠船数据`, not from the full parquet; `scripts/convert_parquet_to_ais_csv.py` converts a 10-month parquet directly to `ais.csv.gz`, not to a date-range CSV. So we need a new extraction script.
2. **Create `scripts/extract_feichang_from_parquet.py`**: Read the full `output/merged_feichang_ships.parquet`, filter by `timestamp_ms`, and write `output/merged_feichang_ships_2021-10-01_2021-11-30.csv` with identical columns (`mmsi,lon,lat,status,sog,cog,heading,rot,timestamp_ms,group_id,datetime,timestamp`). Optionally also write a `.parquet` for future reuse.
3. **Update Node.js build scripts**: Change `CSV_PATH` in `scripts/build-data.js`, `scripts/extract10k.cjs`, and `scripts/compress-csv.js` to point to the new 10-11 CSV.
4. **Regenerate artifacts**: Run `node scripts/build-data.js`, `node scripts/extract10k.cjs`, and `node scripts/compress-csv.js` to regenerate `api/lib/record1.json`, `api/lib/data_10k.js`, and `public/data/ais.csv.gz`.
5. **Update frontend progress estimate**: If the 10-11 record count differs significantly from 535,276, update `estimatedTotal` in `src/lib/aisData.ts` so the loading progress bar remains accurate.
6. **Size caution**: The 10-11 CSV will likely contain ~1M+ rows, making `record1.json` potentially >100 MB. To avoid GitHub file-size warnings, either limit `record1.json` via `RECORD_LIMIT` or skip committing it (it is regenerated by Vercel `prebuild` anyway). The critical runtime data is `data_10k.js` (API) and `ais.csv.gz` (frontend).

## Architecture

- Parquet (source of truth) → Python extraction → date-range CSV → Node.js build scripts → API JSON/embedded data + frontend gzipped CSV.
- No backend or frontend code logic changes except path updates and possibly a progress constant.
